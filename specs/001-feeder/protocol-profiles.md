# Device profiles and release criteria

The electrical process may use synthetic measurements. Every advertised protocol role must exchange native traffic and implement all mandatory behavior for its pinned standard edition and declared profile. Before implementation, record the exact editions, amendments, role, required options, unsupported optional functions and applicable test procedure versions. Resolve every mandatory requirement against the normative text. The profiles below are implementation targets.

| Device role | Target profile | Required evidence |
|---|---|---|
| Feeder IED and station HMI | IEC 61850-8-1 MMS server and client. Model breaker feedback, controls, measurements, quality and timestamp through IEC 61850-7-2/-7-3/-7-4. Engineer the station in SCL per Part 6. Declare report types and the control model. | Validate SCL and its consistency with the live server. Test model discovery, reports, control acceptance and termination as applicable, position feedback, disconnect and reconnect against external peers. Record PICS, MICS, PIXIT and TICS as applicable. |
| Feeder IED and peer IED | IEC 61850-8-1 native Ethernet GOOSE publisher and subscriber. Use engineered datasets and control blocks. | Verify SCL binding, dataset and configuration revision consistency, state and retransmission sequence behavior, time allowed to live and subscriber handling of expiry, restart and configuration mismatch. Use an independent peer and capture at Layer 2. |
| Station gateway and IEC 104 master | IEC 60870-5-104 controlled and controlling stations. Publish an interoperability list with supported ASDUs, causes of transmission, address map, quality, timestamps and selected control procedures. | Verify transfer start/stop, interrogation, spontaneous updates, sequence acknowledgement, timers, positive and negative confirmations, and reconnect without replay. Use IEC 60870-5-6 and applicable IEC TS 60870-5-604 cases. |
| Station gateway and DNP3 master | IEEE 1815 master and outstation over TCP as a separate supervisory configuration. Declare subset level, object groups and variations, event classes, polling, unsolicited behavior and control options in the Device Profile. | Verify integrity and class polling, event ordering and buffering, flags and timestamps, declared control and response semantics, restart and reconnect. Use the applicable DNP Users Group procedures for the outstation and external peer checks for the master. |

## Architecture and evidence

- Keep native protocol stacks at device boundaries. Target gateway ingestion from the IEC 61850 station model and explicit point mappings out to IEC 104 or DNP3. Preserve quality, timestamp, units and command feedback where the target supports them. Document and test any loss of semantics in translation.
- Pin stack versions after checking maintenance, licensing and profile coverage. Use external implementations or test sets that do not share the stack under test. A Wireshark decode is supporting evidence.
- Create a requirement-to-test matrix per role. Save versioned profile files, configuration, test verdicts, annotated captures and build identifiers. Give every applicable mandatory case a passing verdict. Explain every skipped case against the declared profile.
- Test with realistic load, repeated link loss, restart and recovery. Declare any latency, time synchronization or protection performance target before measuring it. Treat Sampled Values, redundancy, and protocol security profiles such as applicable IEC 62351 parts and DNP3 authentication as explicit profile decisions with their own evidence.
- Use independent interoperability runs as a release gate. Record formal conformance certification separately if obtained and identify the exact tested build and profile.
